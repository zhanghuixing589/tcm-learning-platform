# ChromaDB与Neo4j检索投影

## ChromaDB

Collection命名带模型与索引代次，例如tcm_text_v3_g001。距离度量与嵌入维度写入集合配置，不能把返回distance直接当similarity使用。改模型、维度、切块规则需新代次，索引检查完成后切换有效代次。

记录ID：revision:{revisionId}:segment:{segmentId}:chunk:{n}:generation:{g}。元数据保存resource_id、revision_id、source_document_id、segment_id、chunk_no、content_hash、embedding_model、generation。正式知识转成检索文本时也保留同样的事实版本和来源，不只存社区文章。

Java对检索结果重新校验有效正式资源及来源资格。停用时先关闭业务可见性并失效缓存，再异步移除索引，因此延迟删除不能造成停用内容继续进入新回答。

## Neo4j

使用Knowledge节点唯一标识resourceId，属性含knowledgeType、canonicalName、revisionId、generation。SourceEvidence节点唯一标识evidenceId。必要时加入SourceDocument节点以便定位来源。

方剂组成投影为FORMULA-[:CONTAINS {role,doseText,evidenceId,sourceRevisionId,targetRevisionId,generation}]->HERB。关系类型固定枚举：HAS_EFFECT、INDICATED_FOR、ENTERS_MERIDIAN、COMPATIBLE_WITH、RELATED_TO。每条边保留两端版本及证据，单纯节点连线不能视为可信出处。

索引任务先建立新代次快照并校验，再切换有效代次；不能用新任务和旧任务交错覆盖同一批边。Cypher使用后端预定义参数模板，禁止把用户自由文本作为可执行查询。

建库最小约束：
```cypher
CREATE CONSTRAINT knowledge_resource_unique IF NOT EXISTS
FOR (n:Knowledge) REQUIRE n.resourceId IS UNIQUE;
CREATE CONSTRAINT evidence_identity_unique IF NOT EXISTS
FOR (n:SourceEvidence) REQUIRE n.evidenceId IS UNIQUE;
```

以上Cypher为设计基线，尚未在Neo4j实例执行。关系问答实验仍需把同一批事实转成文本加入向量库，避免图谱增强仅因独占答案而占优。
