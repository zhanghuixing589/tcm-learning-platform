# 第三阶段第一批：社区基础、版本化文章与长文额度

实施记录更新于 2026-11-24。状态：第一批验收完成，最终规格与质量审查通过，修复后完整后端打包及真实浏览器复验通过。

依据：[业务设计](superpowers/specs/2026-11-20-stage-three-design.md)、[数据与 API 设计](superpowers/specs/2026-11-20-stage-three-batch-one-data-api-design.md)及[实施计划](superpowers/plans/2026-11-20-stage-three-batch-one.md)。工作在隔离分支 `codex/stage-three-batch-one`，不改写原项目数据库或账户。

## 已实现后端

- 管理员配置两级分区，成员幂等加入/退出，负责人维护简介、规则和本区置顶；禁用账号同事务撤销成员和负责人关系，解禁不自动恢复。
- 讨论与评论直接发布，保留不可变版本、作者历史和源文本差异；评论为两层结构，可指定回复对象，删除保留回复及安全占位。
- 文章使用私有草稿、冻结投稿、审核发布和公开指针；新稿不替换旧公开版。作者修改与状态命令使用版本锁，审核再次检查资格、分区及治理状态，普通批准不能解除暂停。
- 正文仅统一换行，不去掉缩进与首尾空白；额度按 Unicode 码点计算。文献使用稳定 UUID 和版本快照，普通保存不暗改编号；显式重排同步更新正文并重新解析，语义变化时整体回滚。
- 长文额度独立申请、非自批审批，额度、申请、审计和通知原子提交。首次长文可显式取得仅标题的私有草稿身份，空正文不能提交；扩容批准不发布内容。
- 同键重试不重复产生对象或通知，旧版本回执不会冒充后来的新稿。涉及文献的跨文章 UUID 检查采用数据库串行锁，代价是该类写入串行执行。

## 已接入界面

社区列表与两级导航、分区成员/规则、讨论编辑与版本对比、评论分页和安全占位、文章编辑/文献重排/额度申请及分区、额度、政策管理均接真实 API。旧通用资源页复用正式版元数据，不为排版额外累计一次浏览。正文采用受限 Markdown，评论和旧纯文本版本保持文本显示。

首次超长文章显式建立私有身份后保留未保存全文；额度刷新不替换正文或偷偷推进编辑版本锁。会话失效会卸载私有界面，不能被未保存提示阻止。评论冲突有保留输入和核对新版本的恢复流程；隐藏/删除目标的旧昵称和预填原文会清除，真正修改过的文字只作不可提交草稿保留。

## 数据与旧版兼容

V1–V6 原文保留；增加 V7/V8 Java 迁移与 V9 SQL，新增 11 张业务表并扩展 3 张社区表，应用库共 84 张业务表。旧正文保持 PLAIN_TEXT/LEGACY，资源 ID、版本 ID、状态和首次发布时间保留。

系统历史容器表示未分类：迁移前已公开文章可以在候选修订中首次选择正式分区，批准前旧正文、文献、指针和归属保持不变，批准时原子切换。已经归入正式分区的文章仍不能由作者自行改区。

删除带额度历史的最后一份私有草稿会保留不可重开的归档记录并撤回待审申请，保留审批与审计；旧创建请求重试不会复活内容。
