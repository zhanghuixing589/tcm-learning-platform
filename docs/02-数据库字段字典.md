# 数据库字段字典

## V10知识分类增量（2026-11-25）

- content_categories追加knowledge_type VARCHAR(24) NULL、legacy_archive TINYINT NOT NULL DEFAULT 0、lock_version INT NOT NULL DEFAULT 0。启用的新KNOWLEDGE目录必须绑定六种类型之一；仅历史归档允许无类型，且必须停用。其他scope类型列为NULL且不归档。添加同类型名称唯一索引、按类型/启用/排序索引及CHECK，类型/归档身份不可变。
- content_tags追加lock_version，保留原name唯一、active、ID及其全部外键；revision_tags结构不变，知识草稿/修订开始实际读写并复制版本标签，跨知识类型复用相同tag_id，不另建重复标签表。
- 类型赋值触发器依据knowledge_entries身份校验content_revisions的新category_id，拦截跨类型、归档及停用目录；不追溯改写既有冻结版本。新建/修改、提交与审核还会由应用层校验并加共享锁。
- 原KNOWLEDGE目录保持ID/名称/排序/parent_id及全部历史引用，只读归档；新增31个初始目录。无新业务表，无删除原数据，原已执行V1–V9不变。完整SQL为backend/src/main/resources/db/migration/V10__knowledge_taxonomy.sql，语义与迁移约束见[分类契约](../contracts/knowledge-taxonomy.md)。

## 运行态增量说明（2026-11-19）

下文原模型条目保留为设计基线。第二阶段通过 V5/V6 增量迁移增加：

- knowledge_revision_names：revision_id 主键/版本外键，knowledge_type、canonical_name。候选规范名称固定到版本，审核通过才更新 knowledge_entries 的正式名称。
- knowledge_revision_aliases：revision_id + alias 联合主键，关联版本；审核通过才刷新正式 knowledge_aliases。
- file_upload_grants：file_id + user_id 联合主键，外键均 RESTRICT，记录 original_name 与 created_at。全局文件哈希去重不等于向所有用户开放文件访问。
- knowledge_entries.canonical_name 可空：未发布稿不占用正式名称，正式类型/名称的唯一约束保留。

V4 的 user_follows 与上述三张新表使当前运行态为 73 张业务表。迁移原文及当次执行结果优先于基线表数；不原位改写 V1–V4。

共69张表，149条外键。完整设计、分阶段实现。

所有ID在API按字符串返回；时间UTC；外键RESTRICT。以下约束不能替代业务权限和状态转换校验。
