# 本地开发与运行

## 环境与依赖

- JDK17；本机路径 `D:\develop\Java\jdk-17`。
- Maven3.9.9；本机路径 `D:\develop\apache-maven-3.9.9\bin\mvn.cmd`。本机系统mvn命令为占位，使用真实路径。
- Node22.22.3；前端 `npm ci` 按 package-lock.json 安装。
- Python3.11；本次通过项目runtime下的uv安装3.11.18，ai-service/.venv独立使用该解释器，不修改系统默认3.9。
- MySQL8.0.16+。本机验证使用 `D:\develop\mysql8.0\bin`，独立数据目录与随机端口，不访问现有服务。

新机器已有Python3.11时：

```powershell
py -3.11 -m venv ai-service\.venv
ai-service\.venv\Scripts\python.exe -m pip install -r ai-service\requirements.lock
Set-Location frontend
npm ci
npm run build
```

没有3.11时可用uv安装后创建虚拟环境：`uv python install 3.11`、`uv venv --python 3.11 ai-service/.venv`，再安装锁文件。本仓库不会提交解释器或虚拟环境。

## 隔离验收库与快速启动

以下命令在项目根执行：

```powershell
python scripts\dev_mysql.py start
.\scripts\test-backend.ps1
.\scripts\dev.ps1 start
.\scripts\create-admin.ps1
```

dev_mysql.py只创建本项目runtime下的独立实例。状态文件保存端口与随机数据库口令；不会连接现有MySQL。Flyway在新空库自动执行V1/V2，不启用baseline-on-migrate，禁止clean。测试创建的账号仅存在隔离验收库，不是产品种子数据。

应用默认：前端127.0.0.1:5173、Java8080、AI8000。`dev.ps1`可通过BackendPort/FrontendPort/AiPort参数修改；端口占用时失败，不结束其他程序。三端后台隐藏运行，日志在runtime。启动会等待Java readiness与AI health；首次启动会受本机磁盘和类加载速度影响。

测试脚本支持 `-Maven`、`-JavaHome`；数据库工具支持 `--mysql-bin`；应用启动支持 `-JavaHome`。停止助手核对PID和启动时间，避免误停复用PID的其他进程。

## 管理员初始化

不提供默认账号密码。`scripts/create-admin.ps1`交互读取新用户名和隐藏密码，使用BOOTSTRAP_ADMIN_USERNAME/BOOTSTRAP_ADMIN_PASSWORD进程环境调用Java的`--bootstrap-admin`，完成后清除环境并退出。只允许新建账户，禁止借初始化命令提升已存在用户。授予LEARNER和ADMIN，不授予REVIEWER。

注册与新建管理员密码统一为10–12位，必须同时含大写字母、小写字母，以及数字或半角特殊符号；只允许ASCII可见字符（U+0021至U+007E），不允许空格、中文、其他语言文字、全角字符或Emoji。数字和特殊符号可以同时出现。后端在请求DTO和注册Service入口均校验，前端同步提示和校验。BCrypt的72字节检查仅为底层防御，不代替业务规则；数据库继续仅保存BCrypt哈希。既有账户的密码不自动修改，登录保留历史密码兼容性。

## 手动运行与真实开发库

`.env.example`只说明配置名，Spring不会自动读取该文件；请通过PowerShell进程环境或IDE运行配置传入。必填DB_PASSWORD、JWT_SECRET（至少32随机字符）、AI_INTERNAL_TOKEN（至少32随机字符）。真实库必须由开发者明确创建并授权，不要将独立验收库口令用于真实数据库。

```powershell
# 已在IDE或当前进程配置上述环境变量后
Set-Location backend
& 'D:\develop\Java\jdk-17\bin\java.exe' -jar target\tcm-platform-0.1.0.jar

# 单独终端，从ai-service运行
.\.venv\Scripts\python.exe -m uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000

# 单独终端，从frontend运行
npm run dev
```

开发时COOKIE_SECURE=false仅限本地HTTP；生产默认true并使用HTTPS。ALLOWED_ORIGINS为精确Origin列表；浏览器通过同源/api代理，刷新与注销加自定义CSRF头。访问令牌不写入localStorage/sessionStorage。

## 停止与历史工具

```powershell
.\scripts\dev.ps1 stop
python scripts\dev_mysql.py stop
```

两条命令停止本次应用和独立数据库，保留连接状态与原数据目录；重新start复用已有账号。应用停止同时处理venv解释器子进程，并用PID与启动时间ticks防止误停其他进程。需要打包Java时先停止正在运行的应用，避免Windows文件锁阻止jar重命名。

`python scripts/check_mysql_restart.py`验证独立库停止/重启后账号数量不变，运行前先停止应用。该检查只操作本项目runtime中记录的独立实例。

浏览器刷新采用Web Locks跨标签串行，本机Edge与localhost安全上下文已纳入验收；登录/注销通过BroadcastChannel使其他标签失效。访问令牌只保存在每页内存，任何跨账号的旧响应/重试都会被会话代次拒绝。

`scripts/generate_design.py`是原始设计生成工具，会覆盖设计交付文件，进入业务开发后不要在现工程重跑。原V1/V2不原位修改；后续数据库变更新增Flyway版本。

## 登录会话有效期

`tcm.security.session-absolute-days: 30`：从首次登录起最多30天，刷新不会延长此上限。
Access Token通常15分钟；Refresh Token通常7天且每次刷新轮换，两者到期时间均不能超过本次会话的绝对期限，Cookie的Max-Age同步缩短。
即使持续使用，满30天也必须重新登录；连续7天没有刷新时仍会提前过期。登出、停用账号及刷新令牌重放仍会立即撤销会话。
V3新增`auth_refresh_tokens.absolute_expires_at`。旧会话按同一用户同一family最早`created_at + 30天`回填，已超过期限的会话撤销，V1/V2保持不变。

## 切换分支后的Vue解析错误

2026-11-18遇到：页面报`[vite:import-analysis] Install @vitejs/plugin-vue to handle .vue files`。当时插件已安装、配置含vue()，但运行中的Vite在切换到仅README的分支时，因配置文件消失重启并使用默认配置；恢复源码后，旧进程没有重新加载Vue插件。直接请求AdminLayout.vue和PortalLayout.vue均返回500。

处理：重启前端并显式传入`--config vite.config.ts`。npm run dev与一键启动脚本均指定配置，脚本在启动前也检查文件存在。配置缺失时直接报错，避免以默认配置启动。切分支导致配置/依赖变化后应重启开发服务。

验证应检查Vue组件已编译、页面无错误浮层，以及登录等真实页面流程，不能只以index.html返回200判断前端正常。

本次修复验证：两个布局模块从500恢复为200，响应包含Vue编译结果；9项单元测试、4项真实Edge端到端测试和生产构建通过。原失败日志及检查结果保留在本机runtime/vite-recovery-20261118中。
