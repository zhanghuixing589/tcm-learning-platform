# 数据库关系与业务规则

## 1. 建模规则

MySQL InnoDB、utf8mb4_0900_ai_ci，所有表具备BIGINT主键与UTC时间。MySQL会话和连接池统一设置+00:00。DDL由V1管理，角色和分类由V2初始化。不存在真实账户、密码、API密钥或医学内容种子。

资源身份content_resources、内容版本content_revisions和类型专属表共同组成实体。公共正文不是把全部业务塞入JSON；药材属性、方剂组成、题目选项、答题、审核和关系均独立关系化。JSON仅用于配置、事件补充属性和不可变快照。

所有业务外键RESTRICT：停用账户或内容不级联删除历史。点赞、收藏等关联可以物理删除；正式版本、来源段落、试卷快照和审核记录保留。私有问答用户删除后归档并从普通查询隐藏；后续按明确保留策略清理，不能宣称已经完成物理擦除。

## 2. 状态机

| 对象 | 状态变化 | 说明 |
|---|---|---|
| 内容版本 | DRAFT→IN_REVIEW→APPROVED或REJECTED；待审核可WITHDRAWN | 退回或撤回后复制成新DRAFT；不原位改已提交内容 |
| 资源可见性 | DRAFT→PUBLISHED→SUSPENDED；合法复核后可恢复；可ARCHIVED | 审核通过与公开发布在同一应用事务中落实，原公开版本在新稿审核期间保持 |
| 来源资料 | DRAFT→IN_REVIEW→APPROVED或REJECTED/WITHDRAWN | 重提新建资料记录并指向parent_document_id；解析状态独立 |
| 审核任务 | PENDING→APPROVED/REJECTED/WITHDRAWN | 领取只设置reviewer；必须校验非本人、角色和乐观锁 |
| 异步任务 | QUEUED→RUNNING→SUCCEEDED；失败RETRY_WAIT或DEAD | CANCELLED终止，过期租约可重新领取 |
| 作答 | IN_PROGRESS→SUBMITTED或ABANDONED | 提交后标准答案、题干、得分和用户答案冻结 |
| 错题 | PENDING→REVIEWED；再答错回PENDING | 历史作答不清除；复习成绩与首次成绩分开 |
| 问答回答 | GENERATING→COMPLETED/STOPPED/FAILED/REFUSED | 已停止或断线不伪造完成状态 |
| 举报 | PENDING→PROCESSING→RESOLVED或REJECTED | 保留治理操作与通知 |

## 3. 发布与修订事务

1. 锁定审核任务和资源记录，校验操作者权限、待审核状态、submitted_by及源版本。
2. 重新检查来源资格、必填字段与类型规则；任务对应的版本不能在提交后变化。
3. 标记版本APPROVED，更新正式指针和公开状态；知识规范名称及别名索引仅此时刷新。
4. 写review_events、审计、通知与索引任务；同一MySQL事务提交。
5. worker执行检索投影；前端区分公开已完成、索引等待/失败和可检索状态。

资源指针的复合外键保证版本属于同一资源，但版本是否APPROVED必须由事务校验。数据库CHECK无法自动校验其他表的审核状态。

## 4. 来源与历史引用

每份原资料及解析批次独立，document_segments不可原位覆盖。revision_evidence必须关联原文段落或具体位置。方剂组成和关系的依据通过复合外键绑定其起点版本，不能借用其他知识版本的依据。

qa_retrieval_hits记录当时证据；qa_citations保存标题和引用快照。用户可追溯旧版本，当前状态不合格时明确提示，不将旧回答默默改写。停用来源需要查找revision_evidence、卡片知识与题目知识关联，列出受影响对象并停止其不合格检索。恢复经重新审核，不自动恢复所有下游对象。

不是每篇公开社区文章都能被AI检索。社区文章转source_documents时固定origin_revision_id，经来源审核和知识加工后才进入正式检索范围。

## 5. 学习目录、试卷与成绩

专题发布时topic_cards固定卡片版本。用户报名固定专题版本，后续目录改动不静默改变完成率；升级专题版本需要显式迁移目录并保留已完成记录。目录中卡片停用时显示受影响状态，不直接从分母删除来制造完成率。

正式测验模板只引用已审核题目。模板启用后不可原位修改，变更创建新版本。入门建议只用预设规则，不宣称对学习能力作出专业测量。

开始测验：校验所有题目仍有效，创建quiz_attempts、题干选项快照、私有标准答案快照。单选/判断唯一正确选项；多选使用集合完全相等得分，漏选多选均0分。空答案得0分。选项数、正确答案数量、总分和达标分上限由服务端校验。

暂存：校验当前用户、IN_PROGRESS和lock_version。交卷：锁定attempt，读取快照与已存答案，服务端计算分数，一次事务更新题目得分、总分、错题和行为事件。重复提交返回原结果，不能重复增加错题次数。作答API只返回question_snapshot；禁止返回answer_key_snapshot、is_correct或未提交题目的解析。

错题复习创建新的测验作答，可使用REVIEWED标记，但首次成绩不被覆盖。知识薄弱分析从已提交试卷、question_knowledge_links汇总，区分题目版本和复习记录。

## 6. 推荐与实验

用户主动兴趣和计算画像分别保存。新用户无画像时使用主动标签、精选与热度；学习衔接用固定目录，复习用实际错题。内容推荐复用嵌入模型；协同过滤有有效信号才参与，空召回时对有效通道重新归一化权重。

返回推荐不自动算曝光。前端内容实际可见后确认exposed_at；点击携带recommendationItemId，服务端校验属于本人、对应资源及已曝光批次。所有事件使用event_key去重，取消点赞/收藏产生反向事件或据当前有效关联重算，避免不断叠加正分。

内容首次点击/曝光可以用于描述性CTR。不同策略比较需要冻结策略、统一候选范围及预分组；不能将仅向某一策略采集的数据宣称为随机对照结果。研究测试集与人工评分文件保存在ai-service/evaluation-data中，业务数据库不额外建立一套实验管理平台。

## 7. 约束分工

数据库强约束：外键存在性、版本归属、来源段落归属、同帖回复、同会话回复、目标二选一、重复收藏点赞、版本号唯一、分数范围、任务幂等、同场景唯一有效策略、禁止自审。

服务端必验：资源类型匹配、知识类型匹配、卡片属于已报名目录、试题属于合法模板、标准答案选项数、当前操作者所有权、引用属于本轮真实证据、版本已审核、来源有效、所有已提交内容不可变、评论层级、禁用账户撤权和推荐事件归因。当前阶段这些是设计要求，尚未由业务代码实现。

## 8. 查询与索引

常用列表采用owner/user/status与时间的组合索引，所有外键显式建立左前缀索引。中文初始检索使用规范名称/别名前缀与限定数据量的标题匹配，语义检索走向量索引；不宣称普通BTree可以加速任意中文正文包含查询。进入真实数据后用EXPLAIN检查分页、历史、审核队列和推荐事件查询。

初版无分库分表、分区、读写分离。长期增长首先归档事件和运行日志，再依据实际测量决定索引及归档方案。
