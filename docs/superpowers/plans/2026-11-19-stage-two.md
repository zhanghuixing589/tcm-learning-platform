# 第二阶段实施计划

> 执行方式：subagent-driven-development；用户已授权按既有阶段设计实施。冻结接口见同日 stage-two-design.md。全部任务完成前持续推进，不新增确认门槛。

目标：实现来源资料到正式知识的真实闭环；保持此前 main 的身份、个人中心和迁移历史。

## 任务

- [x] 资料处理：source 模块、受控文件存储、不可变解析批次、可重试任务；Python 内部文档解析与测试。
- [x] 内容知识：content/knowledge 模块、候选名称版本化增量迁移、证据与结构化事实、审核发布事务、公开查询、导入/纠错/对比与真实数据库测试。
- [x] 前端：知识中心、来源工作台、知识编辑、审核、任务页、导航和鉴权；真实 API，无假统计或 JSON 编辑器。
- [x] 集成：配置/存储目录/上传限制、来源撤销影响、旧资源入口联动、契约一致性及失败用例修正。
- [x] 验证：Java 完整回归及失败/新增用例定向复验、package，Vue 测试/构建、Python 测试、真实 Edge 来源至发布闭环和既有回归；截图检查。
- [x] 审查与交付：规格符合性、质量与安全审查；修复重要问题，记录实际结果，保留可运行应用。

## 文件边界与检查命令

- 资料实现仅写 backend/.../source、SourceWorkflowIntegrationTest.java、ai-service 和内部解析相关配置。知识实现仅写 backend/.../content、backend/.../knowledge、V5 增量迁移及 KnowledgeWorkflowIntegrationTest.java。二者通过数据库和冻结 HTTP 契约集成。
- 前端实现仅写 frontend；使用 typed API，新增 source/knowledge/review 组件，复用共享客户端与现有布局规范。
- 主执行者维护本计划、task_plan.md/findings.md/progress.md、contracts、运行配置和整体验证。
- 先编写能够揭示缺口的测试，再实现；各实现者先运行自己负责的轻量/定向检查。后端全量测试由主执行者统一执行，避免并发构建 target。
