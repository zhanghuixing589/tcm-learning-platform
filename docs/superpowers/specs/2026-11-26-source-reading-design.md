## 3. 技术路径比较与选择

| 路径 | 优点 | 代价/限制 |
|---|---|---|
| A+. 统一安全AST与不可变阅读版本，叠加能力驱动的多种阅读模式（第二版采用） | 可靠文本共用选文、搜索与溯源；复杂资料保留固定版式/安全预览/纯文本降级；目录与阅读单元解耦 | 需要隔离转换/预览适配器及分阶段能力验收；不能承诺任意排版都能还原 |
| B. 各格式直接嵌入完整第三方阅读器，再分别对接引用 | 可能更接近书籍原始样式 | iframe/样式/脚本隔离及跨格式选文更复杂，CFI和旧片段难统一；仍需新增历史引用模型 |

保留A的安全AST与版本基础，增量升级为A+，不推翻既有审核、引用、MinIO和历史方案。阅读结构表达可可靠识别的正文、注释、图文及表格；它不是唯一展示方式。处理结果分别声明STRUCTURED、FIXED_LAYOUT、PLAIN_TEXT、ORIGINAL_PREVIEW是否真实可用，前端按当前用户和当前阅读单元的有效能力展示工具。

无法可靠确定顺序、脚注关联或表格关系时，不拼出看似完整却错误的正文；优先固定版式安全预览，其次仅对可验证文字提供纯文本视图。没有可靠文字的单元只预览，不开放精确文字引用。旧片段分组仍只算兼容预览。

### 4.1 上传与确认

1. 文件上传是真实POST /files；验证成功后获得fileId、格式、大小和元数据建议。拖放与键盘文件选择具有相同行为；失败不跳到下一步。
2. EPUB提取OPF的title/creator/publisher/date/rights及EPUB3 nav、EPUB2 NCX目录；使用spine决定正文阅读顺序。目录缺失时用实际章节标题/文件名兜底并说明来源。
3. 元数据仅是建议，用户可逐项修正；dc:rights原始文字不自动授予公开或RAG许可。TXT文件名、PDF/DOCX可用标题仅作为建议，缺失字段保持空白。
4. 提供授权类型、版权来源说明、授权依据、允许的使用范围。确认前展示文件/书目/授权摘要。上传完成不等于来源已审核。
5. “确认并解析”在一个受幂等键保护的事务中创建或更新来源草稿并入队解析；重复点击/网络重发返回同一documentId与parseRunId。
6. “保存资料草稿”只保存信息，不自动提交来源审核；以后明确确认时才入队。刷新后可通过已授权fileId恢复元数据建议，不重新上传相同文件。
7. 概览自动轮询真实解析状态，隐藏页降低频率；旧请求不得更新新路由或新账号。失败显示脱敏原因、traceId及本人可操作的重试入口。
8. DOC先完成原件持久化，再由隔离转换器产生DOCX衍生件；复杂排版或按用户需要生成PDF衍生件。转换不可用/失败与原文件已存储分别显示，不把.doc当.docx解压，也不把转换件冒称原件。

### 4.2 资料与审核

概览仅显示书目、授权、解析进度、来源审核状态、阅读/编辑/审核操作。审核信息与解析信息分组，底部不再堆知识编辑器和原文分页。

提交与阅读按可用能力决定，不再要求全部阶段全成功。文件完整性/安全检查通过、原件持久化、书目/授权声明完整，并至少有一种安全阅读模式可用，是提交来源审核的基础门槛。缺失项必须按单元列出，审核员必须明确接受非阻断警告，不能只点一个“通过”忽略缺失。

| 处理情况 | 可读/可整理范围 | 来源审核提案门槛 |
|---|---|---|
| 全部可靠解析 | 按真实能力开放 | 基础门槛满足即可提交 |
| 局部媒体或章节失败，其他部分可靠 | 开放成功单元；缺失位置/图注及警告保留 | 允许提交，审核员确认缺失不影响所批准部分；失败单元禁止引用和检索 |
| 安全预览可用，但没有可靠文字，如扫描PDF | 只预览，无文字搜索/选文/精确文字引用 | 建议允许审核为REFERENCE_ONLY，仅供阅读，不能作为本轮自动文字整理的依据；待确认D2-01 |
| 只有文件或书目已存储，没有安全可用阅读模式 | 不显示可阅读成功 | 保存草稿和允许重试，暂不可提交 |
| ZIP越界/解压炸弹、完整性或安全阻断 | 不因其他单元成功而放行 | 拒绝处理/隔离，不允许审核绕过安全限制 |

待审后仍冻结书目、版权声明、处理结果快照及审核对应阅读版本。未审或退回资料可由所有者私有阅读和整理，但知识提交必须再次验证来源已审、有效、引用单元可靠且具有相应公开引用授权。

部分成功的审核提交携带coverageSnapshotHash及警告列表；审核决定记录已确认的warningId、approvedUse=TEXT_CITABLE/REFERENCE_ONLY和批准覆盖范围。审核员不能把程序判为不可靠或被安全阻断的单元改为可精确引用。后续补齐版不自动扩大已批准的公开/引用范围，须沿来源修订或复核完成新范围确认；原引用仍固定旧版。

## 5. 版权与可见性（四种范围原则已确认，补充第二版细则）

建议分开记录`publicReadingAllowed`、`publicDownloadAllowed`、`quoteDisplayAllowed`、`ragUseAllowed`，由来源审核确认；文件上传者的声明不等于自动公开。

- 只有“来源APPROVED + ACTIVE + 对应授权允许”才开放给普通登录读者。范围是站内登录用户，不把MinIO桶改成匿名公开。
- 所有者可私下阅读本人上传的原文件；专业审核员可访问审核所需内容。管理员身份不自动具有专业审核能力。
- 可以允许公开摘录而不开放全书阅读/下载；不能因知识页展示了一段引文，就让其他用户读取整本书或同版本所有图片。
- 新来源默认不公开全文或下载；公开引文、RAG使用分别声明并审核。授权不明确时只能私有整理，不能发布新的公开引用知识或生成索引任务。
- 旧来源迁移标记LEGACY_UNCONFIRMED，不自动推断许可。保留历史已发布知识中的引文快照与书目信息；整书阅读/下载暂不开放，提示补审授权。不因迁移自动下架既有知识；后续确需撤回来源时走现有停用与治理流程。
- 原文件、章节、图片、全文搜索、阅读进度和精确定位接口均检查同一来源范围；旧/files/{id}也必须补授权约束，防止绕过新阅读器下载全书。

### 5.1 阅读、贡献与受限引文

阅读许可不授予贡献资格。选文保存/加入知识草稿必须校验`contribution:submit`、来源/单元访问权和引用适用范围；公开知识提交再校验`quoteDisplayAllowed`、来源审核与有效性、可靠定位和知识审核条件。本人未审来源仍可私有整理，不代表可公开。只有全文阅读许可、但没有公开引用许可的资料，不能通过阅读器发布其引用知识。

只允许公开引用、不允许全文阅读时，学习者进入受限引文页。服务端按已公开知识版本+evidenceId校验，返回该条允许展示的引文快照、书目、页/单元位置与范围说明；不得接受任意文档ID和用户自造引文来查询全文，也不得返回整章AST、整页图像、所有摘录或可扩大的全文上下文。个人摘录只对摘录所有者开放。

### 5.2 撤回授权与历史

历史引文持久化和公众能否继续看是两回事：快照不删除，但有效访问范围按当前授权决策判定。

- 仅撤回全文阅读/下载、仍允许公开引用：已有合法公开引文继续展示，整书与原文件入口立即关闭。
- 撤回公开引用或来源被停用：相关公开引文不再返回正文，页面说明受限原因；依赖该来源的知识沿现有来源有效性规则暂停公开，等待替换依据/复核，不自动删改已批准正文。
- 审计人员在明确权限范围内可查看冻结历史。已审版权快照不被后台直接改写；撤回事件独立记录操作者、原因、时间、作用范围和版本，再更新有效门禁。不能通过选择旧readingEditionId绕过撤回。
- 未来授权恢复仍需复核，不能由旧缓存/旧异步任务或旧版本复制自动恢复公开。

### 5.3 PDF原件交付边界

PDF.js使用原始PDF字节时，读者已经获得文件数据；隐藏下载按钮不是技术上的防保存措施。明确不允许向普通读者交付原件时，读取路径改为服务端生成的受限页面图像/安全预览，原文件和Range入口拒绝该读者。预览尚未生成时显示处理中或不可用，不回退为交付原件。

页面图像、已显示文字仍可能被截图或抄录，本平台不宣称DRM或不可复制。公开阅读与下载组合对应的交付策略见待确认D2-02。审核员/上传者访问原件另按职责授权，不向浏览器提供MinIO密钥或长期直链。

书目信息补可选的版次、校注/翻译者、数字版来源和授权依据；不因古籍原著年代或标题，自动把现代校注、扫描图版和出版社电子版判成同一许可。

这里是平台访问规则提案，不对具体书籍版权归属或许可真实性作自动法律判断。

## 6. 阅读器

### 6.1 桌面与移动

- 桌面参考三栏：约220px目录 + 可伸缩正文 + 约340px可折叠知识区；正文限制约65–75ch，右栏折叠后居中扩展。1024–1279宽度目录可抽屉化，避免正文被挤窄。
- 默认“阅读模式”收起知识工作区；“知识整理模式”打开右栏/移动底部面板。两种模式共用当前文档、阅读单元、进度、字号/缩放及选择状态，不跳到另一份正文。排版模式切换也必须使用可靠映射恢复位置，否则说明原因并回到同一单元。
- 顶部精简为返回、书名、解析/阅读版、搜索、显示设置、整理工作区开关；不重复放多组保存/解析/审核按钮。
- 目录支持层级、当前章节高亮与键盘导航；正文内连续阅读本章，上一章/下一章保持明确的位置。
- 移动端全屏阅读：顶部紧凑工具栏、抽屉目录、底部可展开的知识编辑面板；编辑面板独立滚动，不覆盖选中原文和系统键盘焦点；关闭后回到原阅读位置。
- 字号、行距和阅读主题沿既有颜色范围；PDF使用缩放而非改变原始页面排版。所有控件有可读标签、可见焦点及44px触控区域。

### 6.2 分格式策略

| 格式 | 正文呈现 | 目录与定位 |
|---|---|---|
| EPUB | 普通流式资料可结构化/纯文本；固定版式、竖排或复杂注释按能力提供固定版式安全预览 | nav/NCX和spine分别处理；目录节点可指向同一单元内不同位置；不猜测双行注释顺序 |
| PDF（含无文本层） | 允许原件交付时用本地PDF.js；否则用服务端页面预览；可靠文字层可另提供文本视图 | 物理页1基序号及可用页标签；书签目录可以跨多页，无文本层不开放文字能力 |
| DOC | 独立二进制Word校验/隔离转换 → DOCX结构化/纯文本；必要时PDF固定版式 | 目录和页码取实际衍生件，不把转换后页码宣称为原DOC稳定印刷页码 |
| DOCX | 普通正文结构化/纯文本；复杂表格、文本框、注释和版式采用安全PDF衍生预览 | 真实标题/书签/脚注；没有标题就保留无目录状态，不编造章节 |
| TXT | 连续文本和按需加载的TEXT_SECTION单元；明确编码/换行策略 | 没有目录时只提供真实全文/位置导航，不把内部装载区段称为原书章节 |

PDF依赖与worker均本地打包；不增加OCR。仅在原件交付许可成立时使用PDF原文件/Range接口，其他情况只加载经授权的预览产物。禁用脚本、自动外部跳转、嵌入文件和可提交表单。扫描PDF只要安全预览可用便可阅读，但明确提示没有可靠文字层。

全文搜索基于当前阅读版本的规范文本，限制在单一有权访问的来源内，返回章节/页/块位置和有界上下文。它不是RAG搜索，不依赖Chroma。选中搜索结果可跳转并高亮，多个相同句子使用具体命中偏移区分。
只有可靠提取的单元参与搜索，结果说明覆盖范围；不能用“0个结果”掩盖部分单元尚未提取。预览图像中的字不算可搜索正文。

### 6.3 能力模型与复杂排版

阅读版本保存客观处理能力，API再与当前用户角色、来源授权及当前单元能力取交集。能力由服务器从产物派生，不接受客户端把开关改为true。示例为设计载荷，不是某本已验收书籍的结果：

```json
{
  "format": "EPUB",
  "layoutMode": "REFLOWABLE",
  "availableReadingModes": ["STRUCTURED", "PLAIN_TEXT"],
  "capabilities": {
    "hasToc": true,
    "hasImages": true,
    "hasTables": true,
    "hasFootnotes": true,
    "textSelectable": true,
    "searchable": true,
    "preciseCitationSupported": true,
    "fontSizeAdjustable": true
  },
  "warnings": []
}
```

`layoutMode`取REFLOWABLE/FIXED/MIXED/UNKNOWN；模式取STRUCTURED/FIXED_LAYOUT/PLAIN_TEXT/ORIGINAL_PREVIEW。ORIGINAL_PREVIEW表示安全生成的预览产物，不表示直接在iframe中执行原始XHTML或Office文件。

无文本层PDF若预览已就绪，可声明FIXED、[ORIGINAL_PREVIEW]、textSelectable/searchable/preciseCitationSupported=false；若预览尚未生成，就不能提前声明该模式可用。混合PDF的无文字页关闭该页选文/精确定位；整书搜索仍可查询其他可靠单元并说明覆盖范围，不能仅根据整书的true启用当前页文字功能，也不能仅因当前页无文字就关闭整书搜索。

- 多级目录、无目录、多目录节点指向同一HTML锚点均属正常输入；目录不是正文顺序或单元的唯一依据。
- 图和图注组成figure关联；保留原始位置、说明与异常占位，不把缺失图删成无痕空白。
- 表格保留行列、合并跨度和表头；无法可靠还原时以固定版式展示，禁止把错列后的剂量关系当成可整理正文。
- 脚注/尾注/正文注释有独立块角色及前后跳转。古籍竖排、双行小注只保留明确可验证的方向/关联；无法确定阅读顺序时提供预览和警告，不强行横排混接。
- 固定版式EPUB采用包内版式声明及可靠布局信息；渲染适配器未就绪时该模式不可用。纯文本降级仅开放可核对顺序的文字，不能通过去CSS就宣称内容可信。

阅读进度按用户+来源+阅读版本保存，记录章节/页/块位置、字体设置和写入版本。节流保存并防止多标签页旧回写；账号切换清除旧内存状态，跨设备恢复由服务器记录决定。新解析出现后明确提示可切换，不按百分比猜测旧位置。

## 7. 原文选择与知识编辑

1. 在具备可靠文字能力的单元选中原文，浮动工具栏按真实状态提供：新建知识草稿、添加到当前草稿、添加到其他草稿、保存个人摘录、复制原文。没有当前草稿时禁用相应动作并解释，不出现虚假的已保存状态；无贡献资格者只开放其许可内的阅读/复制行为。键盘和移动端长按同样可调用。
2. 选择本章/本页的一个或多个段落后，后端验证来源、阅读版本、块归属、起止字符和引文一致性，先保存本人摘录，再打开知识工作区。
3. 摘录保存不强行创建标题或正文为空的知识资源。网络失败时保留当前选择、显示未保存及重试；不能显示“已保存”却只有前端临时状态。
4. 六类型使用现有枚举CONCEPT/HERB/FORMULA/EFFECT/SYMPTOM/MERIDIAN。共用规范名、标题、别名、正文、类型专属目录、标签与依据；药材使用药性/药味/来源产地/注意事项，方剂使用出处/功效摘要/主治摘要/注意事项和组成。归经、功效等关联使用现有关系编辑，不添加假字段。
5. 原文以引用依据呈现，与人工整理正文分开；不自动推断医疗结论或把整段原文伪装成已完成整理。
6. 一稿支持多条摘录，包括不同章节及其他有权访问的来源；支持移除、回看原文和精确高亮。现有关系/方剂组成的evidenceIndex在删除/排序时继续准确绑定。
7. 规范名输入后查询正式同类型规范名及别名，展示真实匹配。本人条目提供继续现有草稿或发起本人修订；他人条目提供独立修订建议；确为不同知识仍可继续创建，但服务端正式名称唯一约束保留。
8. 保存知识草稿和提交审核使用现有知识协议与校验；把表单抽取为共用组件，不复制一套侧栏业务。保存请求携带明确稿件身份与并发版本，409时保留本地内容并要求查看新版，不覆盖别人改动。
9. 第二次及后续选文默认保持正在整理的稿件上下文，让用户明确选择“加入当前稿”或另建；“其他草稿”只列本人可编辑且类型适合的草稿，不列他人私有稿件。已冻结/状态变化的稿件追加失败时，摘录仍安全保留，不能误写到另一稿。
10. 个人摘录可按来源、时间和关键词查找，跨多本资料收集后集中整理。将摘录加入知识时复制并验证引用快照，个人摘录删除/归档不删除已保存或已发布的知识依据。知识类型、目录、关系校验仍使用现有模块。

## 8. 精确引用、版本和历史

- 阅读版本与文本提取/检索批次有明确关联，但不共用一张段落表；目录节点、阅读单元和块ID只在所属不可变阅读版本中有效。阅读版本具有独立readingVersionNo，不能把“解析批次相同”误当作“所有模式和衍生文件相同”。
- 新引用保存documentId、parseRunId、readingEditionId、章节/页、逐块范围、exact/prefix/suffix、原文件SHA256、quoteText和quoteHash。偏移统一为Unicode码点，前端/Java/Python有明确转换；测试包含emoji、组合字符和跨行/跨块选择。
- 引文由服务器从规范文本重建并核对；不能接受客户端伪造的来源ID、引用版本或任意JSON位置。精确文本默认不trim后当作原样文本保存；旧人工定位协议继续兼容。
- PDF允许仅NFC及空白规范化的匹配并保存可逆位置映射，不做医学字符兼容替换。文字层排版与服务器文本无法可靠对齐时明确失败，转到该页规范文本辅助视图重新选取；不生成虚假精确锚点。
- 新解析只追加新批次/阅读版本；旧引用继续打开旧版本并标识“引用的是第N解析版”。旧块不可用时显示引文快照及原因，不静默跳转到新文本。
- 已冻结来源不允许原PARSE入口重写。历史来源通过BUILD_READER任务从同一原始文件补建阅读版，关联旧成功批次，不改旧片段、不重新审核已冻结书目。不能准确映射的旧片段保留原片段视图。
- 停用来源时阻止后续阅读/搜索/资产读取及知识公开资格/索引，保留审计和历史快照；恢复仍按既有来源/知识复核规则，不自动恢复已停用资源。
- 引用定位包含unitId/unitType；可靠文字使用TEXT_RANGE，固定页面可补PAGE_REGION及规范化坐标。只有页面/区域、没有可靠文字，不得伪装成精确文字引用；首批不做OCR或未经核对的图片转文字。
- 原件、转换DOCX、衍生PDF、页面预览、图片转换均有独立artifactId/hash/生成器版本及父产物关系。DOC的转换PDF页号必须标明“转换预览页”，避免与原文件、其他版本的页码混同。
- 预览型阅读版本可以没有成功文字批次；其parseRunId/textExtractionRunId允许为空，精确文字引用能力相应为false。不能为满足第一版外键要求，给无文本PDF伪造一个成功文字解析批次。
- 部分可用阅读版一旦公开为不可变快照，就连失败单元和警告也固定。以后补齐内容发布新的readingVersionNo并关联supersedesEditionId，不能向已被引用的READY版本原地补写正文、改变顺序或静默替换预览。

## 10. 协作修订状态机（原则已确认）

- 本人现有修订继续走原有入口，不把公开条目的owner_id转给贡献者。
- 他人知识：创建独立proposal，复制正式基准版到提案载荷，记录basePublishedRevisionId；提案正文/事实/依据私有保存，不能让KnowledgeService.latest()把它当成原作者的最新草稿。
- 状态DRAFT → IN_REVIEW → APPROVED/REJECTED；未领取任务可按现有规则撤回。退回后另建可编辑提案版本，保留冻结快照与审核事件。
- 提交者仅能修改/提交自己的提案，不能自行通过。审核者沿knowledge:review且不得为提案提交者；管理员不默认获得专业审核权限。
- 批准时锁原资源，要求基准正式版仍一致、原资源没有未完成的普通DRAFT/IN_REVIEW、来源及分类/关系仍有效。若冲突，返回409并显示具体原因，保留提案，不覆盖原作者工作或自动合并。
- 条件满足后，在同一事务生成正式候选content_revision及结构化子记录，调用统一发布校验/审核效果，更新published_revision_id、生成真实outbox任务，并把proposal与新revision关联。不能用单独SQL跳过KnowledgeService.publicationReady。
- 两个提案同时批准，只允许第一个匹配基准者成功，第二个提示基准已变化并要求人工对照后重新发起。既有收藏、知识ID、原作者身份和历史版本不改变。

| POST /knowledge-proposals/:id/submit或withdraw | 冻结/撤回独立提案，接现有审核队列新target类型 |
| 现有审核决定接口的来源分支 | 增补coverageSnapshotHash、acknowledgedWarningIds、approvedUse和批准范围；缺少必要确认时409，旧审核目标和禁止自审规则不变 |

旧/internal/v1/parse及segments作为兼容入口保留原有有界行为。面向大文件的V2处理控制协议只传任务/原件标识、schemaVersion、请求的处理阶段和短期租约授权，读取来源必须固定到Java授权的输入接口；不接受客户端指定磁盘路径或任意URL。Java保留jobId/runToken、超时和心跳，输入按流校验hash，结果按阅读单元/产物有界上传，最终一次租约条件提交清单。

V2返回executionStatus、overallOutcome、各阶段结果、单元/资源覆盖、模式/能力及结构化警告；PARTIAL_SUCCESS是内容结果，不等于索引成功。主控制响应不返回整本书加所有图片的base64；每个传输块、任务累计字节、staging空间和处理时间各有上限。旧12MB完整JSON限制不能通过无限放大常量来承载50MB图书。

图片只在输出中携带已清洗的包内manifest引用及hash/MIME建议；Java从同一已验证原始包提取其实际字节、重新校验并入MinIO。候选imageRef不是可直接读取的系统路径。这样无需把MinIO凭据交给Python或浏览器，也能避免图像反复base64扩张。

文档转换与媒体转换适配器只接收指定输入产物和有限输出目录，通过受控任务通道回传产物清单。失败可单独重试，不能要求全部重新上传；迟到输出不得恢复旧权限或覆盖新阅读版。上述V2接口仍为提案，第一版新建的readerApi.ts与未连接路由均需重新对齐，不声称已有兼容承诺。

## 12. MinIO接入与迁移

- Compose项目tcm-learning-platform；MinIO私有桶tcm-learning-sources，独立命名卷，不复用vibe-music-data及其他项目卷。API/控制台使用本机回环19000/19001。未来Redis放入相同compose文件，各用独立卷。
- 固定本机实际核查的镜像digest，不声称缓存镜像是最新版本。根身份仅初始化；Java最终使用受限应用身份。凭据仅在ignored runtime或环境中，文档只记文件位置。
- SourceFiles提取SourceObjectStore，保留LegacyLocalObjectStore读取老行；新文件MinioObjectStore。读哪个后端由数据库明确指定，MinIO缺对象不能悄悄回退到碰巧存在的本地文件。
- 拷贝前备份数据库和文件清单；逐fileId读取旧对象，计算SHA256/大小，复制后从MinIO读回核对，成功才事务切换该行storage_backend/bucket/key。失败保留LOCAL、可幂等继续；不改fileId、sha、上传者授权或原文件名。
- 不删除原文件，不修改其他项目存储，不通过改密/重置账户验证迁移。完成后所有目标行均指向实际可读MinIO对象，清单和授权指纹与迁移前一致。
- 首次基础设施启动不等于已切换Java；业务接入和文件迁移需单独验证。

### 12.1 DOC与固定版式转换适配器

- DOC按实际OLE/Word内容识别，与DOCX ZIP格式、RTF或伪造后缀区分；加密/损坏/不支持类型有具体失败原因。不能把改后缀当转换。
- 使用独立受限的LibreOffice Headless适配器，原DOC在MinIO保留不变；生成DOCX用于结构/文字处理，PDF用于复杂版式或按需预览，记录parentArtifactId、输入/输出hash、生成器/参数版本与时间。
- 转换容器属于同一tcm-learning-platform Compose项目，但与MinIO各用独立容器/目录。非root、只读根文件系统、独立临时用户配置、无外网、cap-drop、进程/内存/CPU/磁盘/总时长限制；不挂载Docker socket、宿主用户目录、其他书籍或存储根凭据。
- 禁用宏、外部链接更新、远程字体/模板和嵌入对象执行；只允许固定转换参数和指定输入，不能传入用户控制的命令行选项。每任务使用独立配置和目录，超时后终止进程树并只清理该任务目录。
- `--headless`只表示无界面，`--safe-mode`也不是安全沙箱；隔离、禁宏和资源限制必须另外实现并验证。[LibreOffice官方参数说明](https://help.libreoffice.org/latest/en-US/text/shared/guide/start_parameters.html)支持转换与独立用户配置参数，但不提供“任意文档都安全/无损”的保证。
- 尚未安装或验收该转换器。转换失败可保留原件及书目草稿；只有实际生成并校验的模式才启用。普通DOC转换纳入M1，复杂Word/固定版式质量在M2单独验收。

50/200/5000只是待确认D2-03的测试配置。现有Docker报告可用内存约7.62GiB，且同时运行其他项目；这不能证明单任务能无约束占用该内存。需要测实际峰值内存、临时磁盘、耗时、并发退让和失败恢复后再确定默认值。已验过的约240KB《伤寒论》不能充当50MB教材的容量证据。

新路径采用流式上传/计算hash/写MinIO；处理器按任务受限拉取原件到隔离工作目录，按单元和资产分批处理。避免Java/Python同时持有整本原件、base64、完整解压Map、AST及多份规范文本。元数据XML、单元输出、图片解码和主清单各自有大小限制。

原件一旦存储成功可独立保留，后续阶段失败不需重复上传。超出处理预算时有明确的部分可用或失败结果；不得静默截断后标成完整。长任务续租、超时/取消和旧任务回写检查覆盖转换、预览和产物提交，不只保护原有纯文本解析。

## 13. 状态与索引触发

| 对象 | 状态/门槛 | 不允许的推断 |
|---|---|---|
| 文件 | 实际校验、持久化成功及上传授权 | 上传成功不等于来源通过 |
| 调度执行 | 沿既有QUEUED/RUNNING/RETRY_WAIT/SUCCEEDED/FAILED或终止状态 | SUCCEEDED表示任务执行结束，不单独代表内容完整 |
| 内容结果 | SUCCEEDED/PARTIAL_SUCCESS/FAILED，另记阶段与单元状态 | 只有存储成功、没有可用阅读模式时，不得标成部分可阅读成功 |
| 存储/元数据/转换/预览/结构/文本/媒体 | 分别记录SKIPPED/QUEUED/RUNNING/SUCCEEDED/PARTIAL_SUCCESS/FAILED/BLOCKED及覆盖 | 图片失败不自动否决可靠文字；无文本预览不等于可选文 |
| 阅读发布 | 至少一个可靠、安全、已生成模式后可用；快照可整体或部分可用 | READY不再要求所有媒体、文字及模式完整成功；权限仍独立限制 |
| 来源 | DRAFT/IN_REVIEW/APPROVED/REJECTED/WITHDRAWN + ACTIVE/SUSPENDED | 来源通过不自动发布知识 |
| 知识/提案 | 草稿保存与冻结提交，专业审核通过才更新正式版本 | 草稿/摘录/提案不能被公开检索 |
| 索引 | 仅正式、已审且来源/授权有效的知识版本入outbox | 当前服务未接入时显示等待服务，不能写INDEXED |
| 后续索引回写 | 必须匹配当前正式版本和有效来源/授权/任务令牌 | 旧索引任务不得恢复已停用或旧版本的公开资格 |

PARTIAL_SUCCESS由明确覆盖清单支撑：预期/成功/失败阅读单元及媒体数量、警告code、严重程度、位置、影响能力和能否单独重试。未知覆盖不能填成100%。失败单元与不可靠阅读顺序的文字必须从引用及后续检索映射中排除。程序不代替审核员判断内容完整性，但审核不能绕过安全阻断或伪造缺失内容。

本轮尚无RAG执行器，不为来源创建假“索引已建立”状态；仅在正式知识发布且引用单元可靠、来源/授权有效时生成受版本保护的后续索引任务。扫描图像和失败/不可靠部分不进入文本索引。

## 14. 富文本与资源安全

- 服务端只输出允许的结构节点和属性，Vue组件渲染文本节点；不直接v-html整本XHTML，不执行书内脚本或CSS。
- 移除script/style/iframe/object/embed/form、事件属性、危险协议、meta刷新、外部字体/样式、CSS url、srcset外链和自动网络请求。链接仅允许受控站内锚点或显式用户动作的http/https外链。
- 明确识别的竖排方向、ruby注音/双行注、figure/figcaption、脚注角色和表格跨度可扩展为受限语义节点/枚举属性，不接收任意style字符串。无法验证关系时降级预览，不靠CSS白名单猜出医学阅读顺序。
- 图片仅从包内manifest/关系白名单提取，验证真实MIME、字节/像素/帧数及转换产物；不按扩展名直接放行。图片位置、图注和图文关联保留，局部无法处理不能无痕删除。原有路径、重复项、解压炸弹及DOCTYPE外部获取禁令保留。
- 受控DOMPurify仅作需要HTML兼容片段时的额外防线，不能代替后端白名单；清洗后不得再把未经约束内容拼回HTML。
- 浮动选文与搜索高亮通过Range/mark文本操作，不把原文/关键词拼接进HTML。图片请求、下载和Range接口均按来源上下文重新鉴权。
- 验收监控实际外部请求、alert/pageerror及脚本副作用，不能只用字符串正则断言“已经安全”。

### 14.1 媒体处理与降级

| 输入 | 第二版展示策略 | 转换不可用/失败时 |
|---|---|---|
| PNG/JPEG | 实际解码信息及预算校验后受控展示 | 保留位置/图注/错误；不整书失败 |
| GIF | 有界安全解码，默认静态首帧，说明动画/多帧未完整展示 | 占位并记录可能缺失内容，不宣称完整 |
| WebP | 通过已验证解码器校验后展示或转换安全PNG | 保留原始关系和受限提示 |
| SVG | 禁止浏览器直接加载主动SVG；经清洗及隔离渲染器静态栅格化PNG | 占位/图注/失败code；不回退到原SVG或data URI |
| BMP/TIFF | 按需有界转换PNG；多页/多帧必须明示覆盖范围 | 占位及范围提示，不静默仅显示第一帧并称完整 |
| 损坏或未知格式 | 拒绝直接显示，仅保留安全元信息与来源位置 | MEDIA_UNSUPPORTED或具体安全错误，审核可见 |

转换器必须限制网络、外部delegate、读取路径、总像素、帧数、临时磁盘和运行时间。若采用ImageMagick，不可沿用开放默认策略；[官方安全策略文档](https://imagemagick.org/security-policy/)明确支持限制coder、外部操作和资源。具体引擎/固定版本在对应里程碑验证，不能只因有一个转换命令就标为支持。

固定版式EPUB安全预览在隔离渲染器内生成，不向用户页面注入原书HTML/CSS；关闭脚本、表单、远程资源及越界文件访问，浏览器自身沙箱保持启用。关闭JavaScript不等于阻止CSS/图片网络请求，二者都要单独验证。脚注/竖排/表格无法可靠抽取时优先保留预览并限制引用能力，不以错误AST通过验收。
