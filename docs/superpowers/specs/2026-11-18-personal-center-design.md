# 个人中心改版设计方案

日期：2026-11-18。状态：用户已确认布局与设计方向，进入实现与验证。本文保留设计要求，实际交付以实现和验证记录为准。

## 1. 定位与现状

将个人中心从“账号资料编辑页”改成“个人主页与学习内容入口”。用户进入后先看见自己是谁、在平台上留下了什么，再快速找回收藏、最近浏览和发表内容。

依据当前代码核对：

- `frontend/src/modules/account/AccountView.vue` 目前直接展示昵称、简介编辑表单及角色说明。
- 项目采用 Vue 3、Element Plus、Pinia，现有品牌为白色、低彩度绿色面板、深绿色主操作。
- `resource_bookmarks`、`resource_likes`、`user_resource_history` 已有数据库设计，对应的个人内容列表 API 尚未实现。
- `content_resources` 与 `content_revisions` 已设计资源归属、发布及版本审核状态；不能把版本数直接当成发表篇数。
- 当前用户 API 尚未暴露头像，数据库已有 `avatar_path`；关注关系需要新增建模。

本方案中的页面、交互和 API 均为拟实现内容。示意标题与占位符只用于说明结构，不作为线上用户数据。

## 2. 方向比较与推荐

| 方案 | 结构 | 优点 | 局限 |
| --- | --- | --- | --- |
| 个人主页与内容列表，推荐 | 顶部身份区，下方主内容与辅助栏 | 兼顾个人辨识度、社交关系和找回内容 | 需要明确本人私有内容与公开主页的边界 |
| 学习仪表盘 | 学习时长、进度、趋势占首屏 | 适合成熟的课程学习业务 | 当前没有完整学习业务，容易堆积空图表 |
| 左侧账户菜单与右侧设置 | 以资料、安全、资格为中心 | 设置维护清晰 | 仍然偏账户后台，收藏与发表存在感不足 |

选择第一种。参考知乎个人主页的身份与内容分层、豆瓣“个人收藏”的内容优先，以及现有 Element Plus 的标准操作习惯；仅参考信息组织，不复制其他产品皮肤。

设计自检：不为“中医”自动引入米黄宣纸、书法字体、药材插画；项目已有绿色品牌，继续使用。也不将获赞、关注、粉丝拆成三张大型统计卡。视觉记忆集中在清晰的个人名片和有序的内容列表。

## 3. 桌面布局

内容宽度沿用 1120px，与现有导航和页脚对齐。顶部个人名片约 190–220px 高；下方采用约 760px 主内容、32px 间距、约 280px 辅助栏，均使用可伸缩布局。

```text

│ 全站导航                                      个人中心       │
├──────────────────────────────────────────────────────────────┤

│         加入日期                                             │

│ 全部  知识条目  学习专题  社区文章         │                  │
│                         搜索当前列表      │ 内容贡献         │
│                                           │ 贡献资格与状态   │
```

示意中的“—”表示未加载或尚未接通，真实接口成功返回且无数据时才显示 0。

身份区使用整块浅绿色背景、12px 圆角、24–32px 内边距。主体内容用白底、留白与列表分隔线组织，辅助栏通过标题和间距分组，不继续嵌套卡片。

所有内容左对齐。头像约 80px，昵称为首屏视觉中心；数据字号适度，避免抢过用户身份。退出登录放入账户设置，降低日常浏览时的干扰。

## 4. 视觉规范

### 颜色

以下以项目现有 OKLCH 颜色为准；十六进制值仅作近似视觉标识，不替换现有 CSS token。

| 角色 | 近似色 | 实现 token |
| --- | --- | --- |
| 页面与列表背景 | 白色 `#FFFFFF` | `oklch(1 0 0)` |
| 主要文字 | 深墨绿 `#1B241E` | `oklch(0.25 0.015 150)` |
| 主操作与选中态 | 深绿色 `#167039` | `oklch(0.45 0.12 150)` |
| 身份区与辅助底色 | 极浅灰绿 `#F1F6F2` | `oklch(0.97 0.006 150)` |
| 次级文字 | 灰绿色 `#465449` | `oklch(0.43 0.015 150)` |
| 分隔线 | 浅灰绿 `#CFD7D1` | `oklch(0.87 0.008 150)` |

绿色用于主按钮、选中标签和关注状态。待审核、退回等状态同时提供文字，不依赖颜色区分。最终实现时以浏览器实际渲染颜色核验正文至少 4.5:1 对比度。

### 字体、尺寸与细节

- 中文以苹方、微软雅黑和系统无衬线为主，不新增远程字体依赖。
- 昵称 28px/600，内容区标题 20px/600，内容标题 17px/600，正文 16px，辅助信息 14px。
- 主要间距采用 8、12、16、24、32px；模块之间比模块内部更疏朗。
- 圆角：身份区 12px，普通控件 8px，身份标签可用小圆角或胶囊。
- 使用统一风格的线性图标，图标不替代文字说明。头像承担人物识别，不额外添加装饰图。
- 切换、收藏与关注反馈约 150–200ms；不增加页面入场动画。尊重减少动态效果设置。

UI/UX Pro Max 的通用设计系统检索返回了不适合本页的营销结构；收窄检索也未找到匹配的产品方案，因此未采用其配色、字体或布局。本方案依据项目既有规范及通用产品交互原则，结合检索得到的语义控件、键盘导航建议制定。

## 5. 个人名片与互动数据

### 个人资料

展示头像、昵称、面向学习者的角色标签、简介、加入日期。不在公开主页展示登录用户名、权限编码、最近登录时间或后台角色细节。管理员仍可通过现有导航进入后台。

无头像时使用昵称首字加品牌浅底色；无简介时本人看到“写一句介绍，让大家认识你”，访客看到“暂未填写简介”。长昵称换行或截断时提供完整内容访问方式，不挤压编辑按钮。

“编辑资料”进入独立子页 `/account/settings`，提供头像、昵称、简介的预览与保存。头像上传需要在实施时接通现有文件存储能力，并校验类型、大小与访问路径；先保留现有头像直到新上传成功。表单有未保存修改时提供离开提示。

### 获赞、关注、粉丝

- 获赞：自己当前公开内容收到的有效点赞总数，不包含本人给自己内容的点赞；取消点赞后减少，暂停公开或归档内容不纳入该口径。
- 点击获赞：在本页主区域展示自己的获赞内容列表，按获赞数排序；只显示每篇内容及汇总，不暴露点赞者的私有记录。
- 关注与粉丝：点击后进入对应关系列表，显示头像、昵称、简介和关系按钮；不让数字成为无响应的装饰。
- 数字采用等宽数字排版，大数可显示“1.2万”，同时向辅助技术提供完整值。
- 同一操作请求期间禁用重复提交；成功后同步更新列表及数量，失败保留原状态并提供重试。

## 6. 主内容区

### 我的收藏：默认打开

面向用户最常见的回访任务，默认进入我的收藏。按收藏时间倒序；筛选全部、知识条目、学习专题、社区文章。资源类型应映射真实资源枚举，不单独生成重复收藏记录。

列表每项展示类型、标题、两行以内摘要、来源名称和收藏时间。存在真实封面才展示小缩略图；无封面时文字布局自然撑开，不批量使用默认大图。

支持搜索当前收藏列表、分页、打开详情、取消收藏。取消后提供短时“撤销”入口；撤销失败给出明确反馈。无收藏时说明“收藏感兴趣的内容，方便下次继续阅读”。内容浏览尚未开放时只显示说明，不提供跳往不存在页面的按钮。

私有问答回答现存于独立的 `qa_saved_answers`，不在第一版混入资源收藏；未来接入时增加明确的私有回答分类与专门适配。

### 浏览历史

按最近访问时间分“今天、昨天、更早”，同一内容只保留一条最近访问记录。当前历史表是聚合表，不将它描述成逐次访问的完整时间线。

展示内容标题、类型、最近访问时间，支持删除单条和清空全部。清空全部需要确认，并明确只清除浏览记录，不影响收藏或发表。空态提示“读过的内容会留在这里，方便回来看”。

### 我的发表

内容范围限定为本人创建的社区文章与帖子；资料上传仍由贡献管理承接，避免把所有类型的资源都叫作“发表”。

一级列表按资源分组，一篇内容一条，不按版本重复展示。二级筛选为全部、已发布、审核中、草稿、需修改；另可查看已下架与已归档。每项展示标题、更新时间、公开状态、最新修订状态，以及有效阅读/点赞/收藏数；阅读数只在真实采集和口径明确后展示。

已有公开版本、同时新修订送审时显示“已发布 · 修订审核中”，分别标注，不能将线上文章误标为未发布。被退回或撤回的修订按既有状态机新建草稿，不直接修改已提交版本。

| 状态 | 主要操作 |
| --- | --- |
| 草稿 | 继续编辑、删除草稿 |
| 审核中 | 查看提交版本、撤回审核 |
| 已发布 | 查看内容、创建修订 |
| 需修改 | 查看审核意见、创建新草稿 |
| 已下架 / 已归档 | 查看状态说明及允许访问的本人版本 |

“发表内容”主按钮仅在权限允许且编辑流程已实现时启用。暂无资格的用户看到申请贡献资格入口及真实申请状态。身份标签不作为“专业认证”展示。

### 我的点赞

显示自己点赞过的公开内容，与“我收到的赞”明确区分。支持取消点赞，交互与取消收藏一致。内容不可用时不给出不可访问的正文或摘要。

### 列表共通交互

- 标签、分类、页码和搜索词写入 URL 查询参数，刷新、返回与分享给自己时保留位置。
- 搜索与筛选互相叠加，切换条件回到第一页；无匹配结果时显示“清除筛选”。
- 每页 20 条，使用标准分页；列表足够密集，避免无限滚动使用户难以找回位置。
- 加载显示列表骨架；错误只影响当前区域，可就地重试，不清除已有个人资料。
- 下架内容保留“内容暂不可查看”的占位及移除操作，避免泄露原摘要；最终标题展示规则服从内容可见性策略。
- 取消收藏、点赞、关注后，数字与列表保持一致；并发请求不得重复增减。

## 7. 辅助栏与公开主页

辅助栏只设置三组：学习入口、内容贡献、账户设置。

- 学习入口：学习模块真正接通后显示最近学习专题与继续学习。此前展示“学习记录将在专题学习开放后显示”，不制造连续学习天数或完成率。
- 内容贡献：展示无资格、待审核、已通过或被退回的真实状态，连接已有申请页面。
- 账户设置：编辑资料、退出登录；安全设置仅在真实实现后增加。

点击关系列表中的用户，进入最小公开主页 `/users/:userId`：保留头像、昵称、简介、互动数量、关注按钮及公开发表列表。本人收藏、历史、点赞列表、草稿、审核意见与账户入口始终私有。公开主页第一版不展开他人的完整关注/粉丝名单。

关系按钮包含“关注、已关注、互相关注”，本人不显示关注按钮。取消关注使用明确操作文字与就地反馈，不弹出打断式对话框。禁用账户不可新增关注；已有关系的计数和列表统一排除禁用账户，恢复后按同一规则恢复展示。

## 8. 响应式与可访问性

- 1024px 以上：名片横排，下方主内容与辅助栏并排。
- 768–1023px：缩小主辅间距，辅助栏移至主列表下方，内容仍使用足够宽的单列。
- 767px 以下：头像与昵称紧凑排列，编辑按钮换到下一行；三项互动数据仍横向排列。四个主标签在 375px 视口完整可见，必要时减小标签内边距，不横向挤出页面。
- 手机端筛选与搜索换行，列表摘要压缩为两行，日期移入辅助信息行；辅助入口置于列表之后，不抢占首屏。
- 目标触控区域不小于 44px；图标按钮具备可读名称。使用原生按钮与链接，不用可点击 `div` 代替。
- 标签页采用标准键盘行为；当前选中项同时用文字重量与底部标记表达。焦点清晰，切换不会将焦点丢到页面顶部。
- 消息反馈支持读屏播报；加载失败不把统计数字写成 0。检查 375、390、768、1024、1440px 以及 200% 缩放下的溢出与可操作性。

## 9. 数据与接口设计边界

以下为建议契约，实施时与现有返回信封、分页、权限和异常规范对齐。

| 能力 | 建议接口 / 数据来源 |
| --- | --- |
| 本人名片与汇总 | `GET /me/profile-summary`，用户资料、公开内容、点赞和关注关系 |
| 收藏 | `GET /me/bookmarks`，`resource_bookmarks` 与可见资源 |
| 浏览历史 | `GET /me/history`，`user_resource_history` |
| 历史删除 | `DELETE /me/history/:resourceId` 与 `DELETE /me/history` |
| 发表列表 | `GET /me/publications`，资源与版本状态合并视图 |
| 点赞过的内容 | `GET /me/likes`，有效点赞与可见资源 |
| 获赞内容 | `GET /me/received-likes`，本人公开文章按有效点赞聚合 |
| 关注与粉丝 | `GET /me/following`、`GET /me/followers` |
| 关注操作 | `PUT /users/:userId/follow`、`DELETE /users/:userId/follow`，重复调用保持幂等 |
| 公开主页 | `GET /users/:userId/profile`、`GET /users/:userId/publications` |

资源收藏、点赞取消以及正文详情复用资源业务接口，实施时统一补齐；只有列表，没有可打开的内容详情或可执行的取消操作，不算功能完成。

新增 `user_follows`：关注人、被关注人、创建时间；有向关系唯一，禁止关注自己，建立关注人/时间与被关注人/时间索引。服务端校验身份、账户状态与资源可见性，不能相信前端传来的所有者或数量。

获赞、收藏数按资源身份聚合，修订不清空原互动。关注与粉丝统一使用同一有效关系过滤条件。第一版直接查询真实关联并正确分页；是否增加统计缓存依据实际查询测量决定。

公开查询只返回允许公开的字段与发布版本；私有接口从登录态确定本人。收藏与历史的不可见占位不得通过详情接口绕过权限。

## 10. 实施与验收建议

确认设计后按以下顺序落实，当前不执行：

1. 拆分个人名片、互动数据、内容标签、列表与设置页，保留并验证现有资料保存和退出登录流程。
2. 接通本人汇总、收藏、历史、点赞及对应资源详情；真实 0、未加载、未开放与错误各自明确展示。
3. 补齐发表管理、权限、公开版本与修订状态及现有贡献资格入口。编辑与审核流程需与内容模块一起验收。
4. 新增关注关系、最小公开主页及关系操作，验证私有内容隔离。
5. 用真实数据验证密集列表与长文本，用测试夹具验证零数据、接口失败、已下架内容和并发操作；夹具不进入生产页面。

重点验收：

- 手机首屏同时识别本人身份、三项互动统计和当前内容标签；没有横向页面滚动。
- 收藏能打开真实详情，取消可恢复；历史能按最近时间分组、单删和清空。
- 一篇已发布内容在修订送审后仍保持公开身份，发表列表不重复计数。
- 刷新、浏览器返回后保留列表条件；设置保存后名片立即同步。
- 关注幂等、禁止自关注，操作后两个方向统计一致，失败不留下错误计数。
- 未授权访客无法读取历史、收藏、私有点赞记录、草稿或审核意见。
- 不以模拟统计、无效链接或静态假内容代替已实现功能。
