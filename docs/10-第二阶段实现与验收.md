# 第二阶段：公共版本、来源审核与知识中心

日期：2026-11-19。状态：本阶段定义的来源、版本、审核发布和知识浏览主流程已实现并通过本次验收。后续检索问答、学习、推荐等仍按各自阶段实施。

依据：docs/05-开发顺序与验收.md、同日 stage-two-design.md 与 stage-two.md 实施计划。

## 实现范围

- 来源资料：贡献者上传 UTF-8 TXT、DOCX、文本 PDF；按实际格式/内容校验，SHA256 去重，每位实际上传者独立授权与文件名。书目 URL 只保存，不任意抓取外部网页。
- 解析：Java 受控读取文件并调用内部 Python 解析；每次建立新批次和片段，旧批次不可覆盖。任务状态、尝试、错误和重试可观察；runToken/租约防止旧回写。调用含 traceId、大小上限与完整请求超时。
- 知识：六种知识类型、版本化名称/别名、药材属性、方剂组成与知识关系、来源证据；人工片段整理与 CSV 批量导入只生成草稿。
- 审核：来源与知识分别冻结提交；专业审核不能自审、需意见和 lockVersion。专业权限与账户管理/技术任务权限隔离；已有文章任务按社区治理权限处理。
- 发布：校验有效来源、目标版本与证据归属后，在事务中变更正式指针、正式名称/别名、审核事件、审计、通知和幂等索引任务；修订不覆盖原正式版。
- 用户端：知识搜索/分类、正文与结构化事实、来源追溯、关系、收藏/历史、纠错、方剂比较。贡献者工作台、编辑器、版本对比、审核和技术任务页接真实 API。
- 停用：来源停用列出受影响内容并阻止知识中心和通用资源接口继续公开无效知识。恢复通过新稿审核，不直接恢复所有下游。

## 数据和事务

V1–V4 原文保留。V5 增加 knowledge_revision_names、knowledge_revision_aliases、file_upload_grants；知识条目的正式名称允许草稿期间为 NULL，候选名不抢占正式名。V6 为每位上传者保存文件名，避免跨用户去重泄露首个私有上传者的原文件名。当前运行态 73 张业务表、6 次迁移（Flyway 历史表另计）。

全局锁顺序为来源文档 ID 升序 → 资源 ID 升序 → 审核任务。草稿提交锁后重核引用集合；冻结稿审核读取当前状态，并发决策只能有一个结果生效。所有 ID 按字符串返回，时间按 UTC ISO8601 返回。

## 业务边界

- 不支持扫描件 OCR。段落整理为草稿是确定性辅助与人工校正，不宣称实现模型知识抽取或医学内容正确性评估。
- Chroma、Neo4j 与真实 RAG 在第四阶段实施；本轮 VECTOR_INDEX/GRAPH_SYNC/REMOVE_INDEX 保持可观察的待处理任务，不伪装为已索引。
- 为避免并发去重时误删共享文件，数据库回滚可能留下不可通过 API 访问的孤立哈希文件。自动孤立文件清理未实现；后续清理必须先与 file_objects 核对，不可仅按文件年龄删除。
- 来源和头像为单机本地持久化目录；不宣称已经实现对象存储或多实例共享文件服务。
- 浏览器验收使用隔离账户及明确标为验收的合成内容，结束后通过业务停用流程撤下测试来源，保留审核历史。
